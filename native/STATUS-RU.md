# VPNkerla: состояние разработки, 11 сентября 2026

Исходники нативного приложения объединены в основную ветку через
[PR #1](https://github.com/bolt-Apk/VPNkerla/pull/1). [Android-сборка № 5](https://github.com/bolt-Apk/VPNkerla/actions/runs/34558831066)
успешно завершилась для коммита `4b7ff16ecd576d4ab8fa7d336d32e7dd87a5d983`.
В готовом APK проверены SHA-256, подпись, название VPNkerla и наличие VPN-ядра
для ARM64. Точная версия и контрольная сумма: [BUILD-STATUS.json](BUILD-STATUS.json).

Android-пилот предназначен для уже выданного персонального ключа. API,
регистрация и оплата в этой сборке не подключены. Исходники отдельного сервера
аккаунтов подготовлены в продуктовом комплекте. Текущий сайт и работающий
VPN-сервис этими изменениями не заменялись.

Пять серверных тестов прошли: одноразовые и истёкшие коды, повторные платежные
уведомления, неверная сумма/режим магазина, изоляция аккаунтов, отзыв устройств,
подтверждение применения ключа и ограничения HTTP. Платёжный и почтовый сервисы
в тестах заменены тестовыми адаптерами.

Flutter 3.47.1 и зависимости установлены, файл зависимостей закреплён.
Локализация сгенерирована штатным генератором. Анализ проекта завершился без
ошибок и предупреждений; осталась одна информационная рекомендация в неизменённом
тесте исходной основы. Шесть тестов нового клиента прошли: импорт REALITY, XHTTP,
Hysteria 2, проверка небезопасного ввода, резервная группа и форма добавления ключа.

Mihomo собран из закреплённого исходного кода (70f0570…), проверка конфигурации
трёх протоколов прошла. Это проверка синтаксиса конфигурации, а не соединения с
VPN-сервером. Добавлен режим подключения по уже выданному ключу без аккаунта и
оплаты. Он не создаёт бесплатный доступ: ключ должен действовать на VPN-сервере.

В GitHub прошли анализ и все шесть тестов клиента, собраны Flutter-код,
`libclash.so`, `librust_api.so` и APK. Для нативных hooks workflow явно выбирает
NDK 28.2.13676358; исправлен поиск ресурсов Clang для bindgen. Последующие
исправления меняют подписи приложения и плитки на VPNkerla и используют
`--split-per-abi --target-platform android-arm64`, чтобы пакет содержал только
поддерживаемую архитектуру. Проверка итогового файла и его SHA-256
зафиксированы в `BUILD-STATUS.json`.

Файл `android-missing-dependencies.txt` описывает прежнюю локальную попытку,
остановленную ограничениями сети и кэша. Это историческая диагностика: в GitHub
упаковка APK уже прошла успешно.

Корневой workflow `.github/workflows/native-pilot.yml` запускает Android-сборку
для изменений в PR и поддерживает ручной выбор платформы. Он восстанавливает
исходники через `native/materialize.py` из `upstream.json`, `upstream.patch` и
`overlay/`, устанавливает средства сборки и сохраняет артефакты с SHA-256. Для
такой сборки не нужны ключи магазина или VPN. Ранее загруженный ZIP содержит
старый снимок; текущие исходники и исправления находятся в основной ветке.

## Что нужно для завершения запуска

1. Тариф утверждён: 279 ₽ за 1 месяц (30 дней), до 3 устройств.
   Единственный тариф сохранён в конфигурации; продажи пока отключены.
2. ЮKassa отложена по просьбе владельца. Позже настроить тестовый магазин и почтового отправителя. Секреты вводятся
   в закрытые настройки сервера, не в чат или исходники приложения.
3. Разместить API за исправным HTTPS, не занимая порты действующего VPN.
4. Испытать проверенный Android APK на физических устройствах. Собрать установщики для остальных
   ОС и настроить подписи выпусков.
   Для iOS нужны разработка Network Extension, Mac и аккаунт организации Apple.
5. Пройти оплату и подключение с реальных устройств; только после этого
   включить продажи и планировать масштабирование.

Смена протокола может помогать при отдельных видах фильтрации, но не гарантирует
обход всех ограничений. VPN не восстанавливает полностью отключённую передачу
данных. «Антизаглушка на всех операторах» не является подтверждённой функцией.

необходимо предоставить соответствующие исходники и сохранить уведомления.
